# STT 문장 재점검 실험

STT가 만든 문장을 정리한 뒤 Qwen에 보내고, 원문을 보낸 결과와 비교하는 AI 담당 개발 모듈이다.

```text
입력 문장 보관
  → 승인 줄임말·메뉴 표기 정규화
  → 자모 편집 거리로 메뉴 후보 확인
  → 직전 질문 문맥으로 짧은 답변 보강
  → Qwen 주문 필드 추출
  → 별도 검증
```

## 현재 범위

- `아아 → 아이스 아메리카노`, `아바라 → 아이스 바닐라라떼` 등 승인한 표현을 정리한다.
- 메뉴 오타가 의심되면 후보를 비교하며, 애매한 메뉴는 확인 대상으로 남긴다.
- 명시적으로 제공한 이전 질문 문맥에서 수량·온도·휘핑 답변을 연결한다.
- 모델이 임의로 수량을 채우거나 다른 메뉴를 반환하면 별도 검증 결과를 기록한다.
- Qwen 원본 답변을 보존하고, 매장 고정값 적용·검증 판정은 별도로 기록한다.

기존 `review_lab`은 **문장 단위 실험**이다. 이 배치 자체는 마이크·STT를 실행하지 않는다. 추가된 `voice_lab`은 실제 SenseVoice 입력을 같은 비교 경로에 연결한다. 두 실험 모두 TTS·자동 대화·장바구니·DB와 프로젝트의 기존 HTTP 주문 API는 구현하지 않는다.

### 11월 24일 추가: 다른 메뉴 문맥과 실제 음성 연결

- [새 20문장 정답 초안](새20문장_정답먼저보기.html)을 모델 호출 전에 확인한다. 기존 학교 결과를 본 뒤 만든 추가 개발 점검이며 최종 시험셋이 아니다.
- `5_새20문장비교.cmd`는 학교 모델로 20개를 비교하고 `records/additional20`에 새로 저장한다. 16개는 필드·질문 유무를 대조하고, 마지막 4개는 보류 여부·질문 내용을 수동 검토한다.
- 첫 12개는 수량·온도·휘핑 질문에 대한 짧은 답변이다. `context_data`에 직전 질문과 이미 알려진 사실을 주고 A/B 양쪽에 같은 문맥을 전달한다. 정답 수량·온도를 미리 넣지 않는다.
- 문장 보정 정책 0.5, Qwen 프롬프트와 생성 옵션은 그대로 유지했다. 추가 사례가 틀리더라도 정답에 맞춰 이번 결과를 덮어쓰지 않는다.
- `voice_lab/server.py`는 실제 SenseVoiceSmall INT8 CPU, 녹음 종료 후 최종 인식, 원문/재점검문 Qwen 비교, 검증 결과와 원본 WAV 저장을 제공한다. 브라우저 기본 음성 인식은 사용하지 않는다.
- 배포 ZIP에는 휴대용 Python·선정 STT 모델·런타임을 넣지만 Git에는 가중치·설치 환경을 올리지 않는다. Git 소스만 받은 상태에서 모델이 준비되었다고 판단하지 않는다.
- 실제 음성의 정답 전사는 자동으로 채우지 않는다. 녹음을 듣고 확인한 전사만 CER에 사용하며, 선택한 정답 초안과 발화 의미가 같다고 사용자가 확인하기 전에는 모델 필드 정답률을 계산하지 않는다.

음성 서버는 `python voice_lab/server.py`로 실행하고 `http://127.0.0.1:8010`에서 연다. 실행에는 배포본의 `models/sensevoice`, `vendor`, `runtime`이 필요하다. 학교 모델은 기존 `school.local.json` 또는 환경 변수로 지정한다. 마이크 없이 `--check-only`로 동봉 합성 WAV를 실제 인식할 수 있으나 사람의 주문 정확도 시험은 아니다.

## 실행

Windows는 Python 3.11 이상, Linux는 Python 3.10 이상과 실행 중인 Qwen 서버를 사용한다. 문장 처리 코드는 Python 표준 라이브러리만 사용한다.

Linux에서는 [리눅스 실행 안내](리눅스_먼저읽기.txt)를 읽고 압축 해제한 폴더에서 `bash 0_시작하기.sh`를 실행한다. 메뉴 1번은 오프라인 준비 확인, 2번은 학교 실제 연결 확인, 3/4/5번은 비교 실험이다. [리눅스 점검 범위](results/2026-11-24-linux/README.md)는 실제 학교 9B 성능 평가와 구분한다.

Windows에서는 다음 파일을 실행한다.

학교에서 9B를 비교할 때는 [학교 실행 안내](학교실험_먼저읽기.txt)를 읽고 `1_학교연결점검.cmd` → `2_학교56문장비교.cmd` 순서로 실행한다. 학교용 ZIP은 Python을 동봉하며 Git 소스에는 실행 환경이 포함되지 않는다.

- **6_문장재점검실험.cmd**: 문장을 하나씩 입력한다.
- **7_자동비교실험.cmd**: 개발용 56문장을 일괄 비교한다.

실행 파일은 `BOM_PYTHON`에 지정한 Python, 폴더 안의 기존 portable Python, 설치된 `py`/`python` 순서로 찾는다. Git에는 Python 실행 파일과 모델 가중치가 포함되지 않는다.

터미널에서 직접 실행할 수도 있다.

```powershell
py -3 review_lab/run_review.py
py -3 review_lab/run_batch.py
py -3 review_lab/run_batch.py --validate-only
```

`--validate-only`는 입력과 보존 규칙만 확인하며 모델을 호출하지 않는다.

### 집 Qwen

기본값은 `http://127.0.0.1:18080/v1`의 `Qwen/Qwen3.5-0.8B`이다. 학교에서 선정한 9B 모델을 대체하는 결정이 아니다.

기존 `bom-qwen08-demo` 컨테이너를 사용한다. 선택 사항인 `2_모델서버실행.cmd`는 NVIDIA GPU를 사용하는 기존 집 실습 구성을 시작한다. 최초 실행에는 큰 이미지·모델 다운로드가 있으므로 이미 실행 중이면 다시 준비할 필요가 없다. 이 Docker 구성을 Intel 내장 GPU 노트북 실행 구성으로 해석하지 않는다.

### 학교 Qwen

학교 주소는 저장소에 넣지 않는다. 명령 프롬프트에서 실제 주소를 지정한 뒤 별도로 실행한다.

```bat
set "BOM_SCHOOL_QWEN_BASE_URL=http://YOUR_SCHOOL_HOST:PORT/ollama/v1"
7_자동비교실험.cmd --profile school
```

학교 모델 이름은 `qwen3.5:9b-q4_K_M`이다. 주소를 지정하지 않으면 요청 전에 안내하고 중단한다. 학교 API 연결과 현재 JSON 요청 형식 지원 여부는 별도 확인 대상이다.

학교 프로필은 Ollama 네이티브 `/api/tags`와 `/api/chat`을 사용한다. `/v1`로 끝나는 설정도 네이티브 기본 주소로 정리한다. JSON schema와 `stream=false`, `think=false`, `temperature=0`, `num_predict=1024`로 요청한다. 집 프로필의 프롬프트와 요청 설정은 유지했다. 서버가 실제로 받는지는 학교에서 별도로 확인해야 한다.

요청 규격: [Ollama chat](https://docs.ollama.com/api/chat), [structured outputs](https://docs.ollama.com/capabilities/structured-outputs), [thinking](https://docs.ollama.com/capabilities/thinking).

## 오늘 확인한 결과

현재 보정은 0.5다. 실제 합성음의 STT에서 발견한 등록 옵션 단어 내부 공백을 정리하도록 보완했다. [추가 실험과 보완 결과](results/2026-11-23-extra/README.md)를 참고한다.

보정 0.4와 검증기 0.2를 기존 집 모델에서 실행한 결과도 보존했다. [2026-11-23 결과와 한계](results/2026-11-23/README.md)에 근거를 정리했다. [이전 0.3 결과](results/2026-11-22/README.md)는 별도로 보존한다.

- 개발 텍스트 56개: 핵심 슬롯 83/128 → 93/128 일치. 의도·질문까지 전체 조건은 8/44 → 13/44 일치.
- 예전 실제 STT 문장 43개: 보이는 문장만으로 정답 초안을 정할 수 있는 18개에서 전체 조건 1/18 → 4/18 일치. 원래 음성·직전 문맥이 없는 항목의 뜻을 추측해 채점하지 않았다.
- 미확인 메뉴를 버리고 알려진 메뉴만 부분 수락하던 오류를 수정했다. 같은 43개 저장 응답의 재검증에서 오류 1 → 0건, 올바른 필드 수락 4 → 4건. 새 Qwen 호출은 없었다.
- 동봉 합성 WAV 한 건으로 실제 SenseVoiceSmall → 현행 재점검 → 실제 집 Qwen → 필드 검증을 확인했다. 사람 마이크 성능 표본이 아니다.
- 개발56 재점검 중앙값 0.083ms, 최대 0.552ms. 모델 응답까지 빨라졌다고 주장하지 않는다.

정답은 **독립 검수 전인 개발 초안**이다. 새 사람 음성·학교 9B·고령자·매장 환경과 전체 주문 완료는 별도 검증 대상이다. 음성 원본이 없는 과거 로그의 CER는 계산하지 않는다. 검증 차단을 모델 정답이나 주문 성공으로 세지 않는다.

`정답표_검토용.html`에서 팀원이 문장별 의견을 기록하고 검수 JSON을 내려받을 수 있다. `freeze_reference.py`는 명시적인 전체 검수 결과가 현재 문장·정답·정책 버전과 맞는지 확인한다. 의견 저장만으로 정답을 자동 변경하거나 독립 시험셋으로 취급하지 않는다.

## 평가 방법

A 원문과 B 재점검문에 같은 모델·프롬프트·메뉴·문맥·생성 설정을 사용한다. 정답표는 모델 요청에 넣지 않는다. 문장이 같으면 실제 응답 하나를 공유하며 B를 별도 호출·0ms 표본으로 세지 않는다.

개발용 정답과 모델 답변의 슬롯·의도·질문 유무를 대조한다. 검증 단계는 확인 없는 잘못된 수락과 올바른 답변의 추가 차단을 별도로 센다. 질문의 실제 적절성, 음성 CER, 전체 주문 완료율은 이 점수로 평가하지 않는다.

자모 유사도는 STT 신뢰도나 정답 확률이 아니다. 이 모듈은 실제 ASR N-best 후보를 재순위화하는 방식이 아니다.
