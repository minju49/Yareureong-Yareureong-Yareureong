# STT 문장 재점검 실험

STT가 만든 문장을 정리한 뒤 Qwen에 보내고, 원문을 보낸 결과와 비교하는 AI 담당 개발 모듈이다.

```text
입력 문장 보관
  → 승인 줄임말·메뉴 표기 정규화
  → 자모 편집 거리로 메뉴 후보 확인
  → 직전 질문 문맥으로 짧은 답변 보강
  → Qwen 주문 필드 추출
  → 별도 검증
```

## 현재 범위

- `아아 → 아이스 아메리카노`, `아바라 → 아이스 바닐라라떼` 등 승인한 표현을 정리한다.
- 메뉴 오타가 의심되면 후보를 비교하며, 애매한 메뉴는 확인 대상으로 남긴다.
- 명시적으로 제공한 이전 질문 문맥에서 수량·온도·휘핑 답변을 연결한다.
- 모델이 임의로 수량을 채우거나 다른 메뉴를 반환하면 별도 검증 결과를 기록한다.
- Qwen 원본 답변을 보존하고, 매장 고정값 적용·검증 판정은 별도로 기록한다.

현재는 **문장 단위 실험**이다. 마이크·STT·TTS·자동 대화·장바구니·DB를 여기서 실행하지 않는다. 프로젝트의 기존 `docs/api-contract.md`에 정의된 HTTP 주문 API 구현도 아니다.

## 실행

Python 3.11 이상과 실행 중인 Qwen 서버가 필요하다. 문장 처리 코드는 Python 표준 라이브러리만 사용한다.

Windows에서는 다음 파일을 실행한다.

학교에서 9B를 비교할 때는 [학교 실행 안내](학교실험_먼저읽기.txt)를 읽고 `1_학교연결점검.cmd` → `2_학교56문장비교.cmd` 순서로 실행한다. 학교용 ZIP은 Python을 동봉하며 Git 소스에는 실행 환경이 포함되지 않는다.

- **6_문장재점검실험.cmd**: 문장을 하나씩 입력한다.
- **7_자동비교실험.cmd**: 개발용 56문장을 일괄 비교한다.

실행 파일은 `BOM_PYTHON`에 지정한 Python, 폴더 안의 기존 portable Python, 설치된 `py`/`python` 순서로 찾는다. Git에는 Python 실행 파일과 모델 가중치가 포함되지 않는다.

터미널에서 직접 실행할 수도 있다.

```powershell
py -3 review_lab/run_review.py
py -3 review_lab/run_batch.py
py -3 review_lab/run_batch.py --validate-only
```

`--validate-only`는 입력과 보존 규칙만 확인하며 모델을 호출하지 않는다.

### 집 Qwen

기본값은 `http://127.0.0.1:18080/v1`의 `Qwen/Qwen3.5-0.8B`이다. 학교에서 선정한 9B 모델을 대체하는 결정이 아니다.

기존 `bom-qwen08-demo` 컨테이너를 사용한다. 선택 사항인 `2_모델서버실행.cmd`는 NVIDIA GPU를 사용하는 기존 집 실습 구성을 시작한다. 최초 실행에는 큰 이미지·모델 다운로드가 있으므로 이미 실행 중이면 다시 준비할 필요가 없다. 이 Docker 구성을 Intel 내장 GPU 노트북 실행 구성으로 해석하지 않는다.

### 학교 Qwen

학교 주소는 저장소에 넣지 않는다. 명령 프롬프트에서 실제 주소를 지정한 뒤 별도로 실행한다.

```bat
set "BOM_SCHOOL_QWEN_BASE_URL=http://YOUR_SCHOOL_HOST:PORT/ollama/v1"
7_자동비교실험.cmd --profile school
```

학교 모델 이름은 `qwen3.5:9b-q4_K_M`이다. 주소를 지정하지 않으면 요청 전에 안내하고 중단한다. 학교 API 연결과 현재 JSON 요청 형식 지원 여부는 별도 확인 대상이다.

학교 프로필은 Ollama 네이티브 `/api/tags`와 `/api/chat`을 사용한다. `/v1`로 끝나는 설정도 네이티브 기본 주소로 정리한다. JSON schema와 `stream=false`, `think=false`, `temperature=0`, `num_predict=1024`로 요청한다. 집 프로필의 프롬프트와 요청 설정은 유지했다. 서버가 실제로 받는지는 학교에서 별도로 확인해야 한다.

요청 규격: [Ollama chat](https://docs.ollama.com/api/chat), [structured outputs](https://docs.ollama.com/capabilities/structured-outputs), [thinking](https://docs.ollama.com/capabilities/thinking).

## 오늘 확인한 결과

2026-11-22 결과는 보정 0.3의 기록이다. 현행 0.4에서는 휘핑 답변 `일반으로/보통으로`와 수량 답변 `세 컵이요`의 문맥 연결을 보완했다. 수정 뒤 모델 정확도를 다시 측정한 것은 아니며, 학교 모델에서 별도로 비교한다.

[2026-11-22 결과 요약](results/2026-11-22/README.md) · [문장별 CSV](results/2026-11-22/comparison.csv)

- 개발용 텍스트 56개, 실제 집 Qwen 호출 79회.
- 정답 초안 채점 대상 44개: 원문 8개 일치 → 재점검 13개 일치.
- 원문 응답 1건은 출력 한도에서 잘렸다. 이를 포함한 개선 5개를 전부 의미 해석 개선으로 보지 않는다.
- 두 경로 모두 정상 JSON인 43개만 비교하면 8개 → 12개 일치.
- 재점검 자체 처리시간 중앙값 0.092ms, 최대 0.455ms. 이번 집 PC의 측정값이다.
- 검증 차단을 모델 정답이나 실제 주문 완료로 세지 않았다.

직접 만든 문장과 정답 초안을 사용한 **개발 점검**이다. 독립 검수, 새 실제 음성, 학교 9B, 고령자 및 매장 환경 검증은 남아 있다. 이전 실제 마이크 로그는 중복 제거·문장 처리 감사만 했으며 모델 점수에 합산하지 않았다.

## 평가 방법

A 원문과 B 재점검문에 같은 모델·프롬프트·메뉴·문맥·생성 설정을 사용한다. 정답표는 모델 요청에 넣지 않는다. 문장이 같으면 실제 응답 하나를 공유하며 B를 별도 호출·0ms 표본으로 세지 않는다.

개발용 정답과 모델 답변의 슬롯·의도·질문 유무를 대조한다. 검증 단계는 확인 없는 잘못된 수락과 올바른 답변의 추가 차단을 별도로 센다. 질문의 실제 적절성, 음성 CER, 전체 주문 완료율은 이 점수로 평가하지 않는다.

자모 유사도는 STT 신뢰도나 정답 확률이 아니다. 이 모듈은 실제 ASR N-best 후보를 재순위화하는 방식이 아니다.

## 파일

| 위치 | 역할 |
|---|---|
| `review_lab/review.py` | 문장 정규화, 메뉴 후보 비교, 명시적 문맥 보강 |
| `review_lab/qwen_client.py` | 실제 Qwen 요청과 원본 응답 보관 |
| `review_lab/order_gate.py` | 단일 추가 주문의 제한된 필드 검증 |
| `review_lab/run_review.py` | 한 문장씩 확인하는 실험 |
| `review_lab/run_batch.py` | 고정 문장·조건의 자동 비교 및 기록 |
| `review_lab/batch_cases.json` | 개발용 문장과 정답 초안 |
| `review_lab/menu_policy.json` | 이번 6개 메뉴·옵션 정책 |
| `results/2026-11-22/` | 개인정보·원본 로그를 제외한 실험 요약 |

`records/`는 실행 시 생성되며 Git에서 제외한다. 원래 USB용 실행본과 대용량 모델은 별도로 보관한다.
