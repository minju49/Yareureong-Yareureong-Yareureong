11월 24일 화요일 · 학교 Qwen 문장 재점검 실험 (보정 0.5 / 검증 0.2)

이 파일로 하는 일
원문과 재점검문을 같은 학교 Qwen 9B에 보내고 결과를 비교한다.
마이크·STT·TTS·프론트·DB는 여기서 실행하지 않는다.
학교용 ZIP에는 Python과 처리 코드를 넣었다. 모델을 PC에 설치하거나 내려받지 않는다.
Git에서 받은 소스만 사용할 때는 Python 3.11 이상이 별도로 필요하다.

무엇부터 누르나
1. ZIP 전체를 학교 PC의 쓰기 가능한 폴더에 압축 해제한다.
2. 1_학교연결점검.cmd를 누른다.
3. 첫 화면에서 실행 위치와 qwen3.5:9b-q4_K_M 모델 이름을 확인한다.
4. 모델 목록 확인 → 실제 주문 한 문장 → 실제 답변과 진단 기록 위치가 나온다.
   점검 한 문장이 맞았다고 전체 정확도 평가가 끝난 것은 아니다.
5. 연결·JSON 확인이 성공하면 2_학교56문장비교.cmd를 누른다.
6. 이 파일도 시작 전에 점검 문장을 한 번 보낸다. 그 요청은 본 비교 점수에서 제외한다.
7. [01/56]부터 올라간다. 실행 창을 유지한다.
8. 끝나면 결과 화면이 열린다. 결과요약.html, 비교결과.csv, summary.json을 보관한다.
9. 개인 전달용 ZIP의 3_실제STT기록43문장비교.cmd를 실행하면 예전 마이크 인식 문장도 같은 학교 모델로 비교한다.
   지금 새로 녹음하는 실험은 아니다. 원래 음성·직전 질문이 없는 항목의 뜻을 임의로 정답 처리하지 않는다.
10. records 폴더를 통째로 복사해온다. 여기에 실제 요청과 원본 응답이 들어 있다.

서버 주소
개인 전달용 ZIP의 school.local.json에 교수님이 알려준 주소를 넣었다.
Git 소스에는 실제 주소를 올리지 않았다. school.example.json을 school.local.json으로 복사해 작성한다.
주소는 /ollama, /ollama/api, /ollama/v1 형태를 기본 주소로 정리한다.
모델 목록은 /api/tags, 주문 요청은 /api/chat을 사용한다.
학교 서버에 접근할 수 있는 네트워크에서 실행한다.

실패하면
- 연결 거부/시간 초과: 학교 네트워크와 교수님 서버 상태를 확인한다.
- 모델 없음: 표시된 모델 목록과 qwen3.5:9b-q4_K_M 이름을 확인한다.
- HTML/잘못된 JSON: 주소·프록시 경로·서버 응답을 확인한다.
- 요청 옵션 오류: 진단 기록의 오류를 확인한다. 프로그램이 옵션을 몰래 바꿔 재시도하지 않는다.
- Python 실행 문제: ZIP을 전체 압축 해제했는지 확인한다. 콘솔 내용을 보관한다.
실패 결과를 성공 수치로 채우지 않는다. 새 설정을 쓰게 되면 A/B 모두 같은 설정으로 새 실행한다.

집에서 열어볼 때
학교 연결 없이 파일 구성만 보려면 명령 프롬프트에서 아래처럼 실행할 수 있다.
1_학교연결점검.cmd --self-check
준비 확인 완료가 나와도 학교 서버·실제 모델 실행을 확인한 것이 아니다.

이번 실험의 고정 기준
- 개발용 텍스트 56개다. 실제 음성 56개라는 뜻이 아니다.
- 44개는 메뉴·수량·온도·사이즈·휘핑·메모·의도·질문 유무를 비교한다.
- 모호한 메뉴 4개와 복합 요청 8개는 모델 정답률에서 빼고 확인 없는 수락 여부만 본다.
- 정답표는 아직 팀원의 독립 검수 전이다. 정답표_검토용.html에서 문장별로 검토하고 검수 JSON을 저장한다.
  수정 필요·판단 보류를 맞음으로 바꾸지 않는다. 검수 전 실행 결과는 정답 초안 기준의 개발 점검으로만 사용한다.
  검수 화면의 저장은 의견 기록이다. 저장했다고 실행 정답 파일이 자동 수정되지는 않는다.
- 수량이 없으면 묻는다. Only Ice는 온도를 다시 묻지 않는다.
- 카페모카의 질문 순서는 수량 → 온도 → 휘핑이다. 이미 말한 것은 다시 묻지 않는다.
- 원문과 재점검문이 같으면 실제 응답 하나를 공유한다. 두 번의 독립 호출로 세지 않는다.
- 원문과 재점검문에는 같은 메뉴·문맥·프롬프트·생성 설정을 사용한다.
- 모델 원본 답변과 별도 검증 판정을 구분한다. 장바구니는 바꾸지 않는다.

생성 설정과 기존 결과 구분
학교 네이티브 API에는 JSON schema, stream=false, think=false,
temperature=0, num_predict=1024로 요청한다. 실제 서버의 지원 여부는 연결 점검에서 확인한다.
think=false는 요청한 설정이다. 서버가 실제로 thinking을 반환했는지는 기록에서 확인한다.
이전 집 0.8B 실험은 다른 모델·전송 방식·출력 한도를 사용했다.
보정 효과는 이번 학교 실행 안의 A/B로 비교한다. 집/학교 점수 차이를 보정 효과라고 하지 않는다.
API 정상 여부와 의미 정답 여부를 분리한다. 질문 내용의 자연스러움은 사람이 따로 확인한다.

09~12시 순서
09:00~09:20  압축 해제, 연결·실제 한 문장 확인
09:20~09:40  팀원끼리 정답 검토, 수정이 있으면 본 실험 전에 고정
09:40~10:10  56문장 실행, 원본 기록 보관
10:10~11:00  개선·악화·JSON 실패·불필요한 질문을 구분해 결과 검토
11:00~11:30  과거 실제 STT 문장의 대표 사례와 비교. 검수 정답 없는 자료는 정확도로 세지 않음
11:30~12:00  수요일 발표에 넣을 방법·결과·남은 검증을 정리
위 시간은 작업 배분안이다. 서버 상태에 따라 조정한다.

수요일에 설명할 핵심
1. 문제: 줄임말·메뉴 오인식·짧은 답변이 주문 해석 오류로 이어질 수 있다.
2. 방법: 승인 표현 정리 + 자모 기반 메뉴 후보 비교 + 명시적 문맥 보강 + 별도 검증.
3. 실험: 같은 모델에 원문/재점검문을 보내 필드 일치·개선/악화·추가 시간을 측정한다.
4. 한계: 개발용 정답 초안, 단일 추가 주문 중심. 새 음성·고령자·현장 환경은 후속 검증이다.
5. 실제 발견한 문제: 모르는 메뉴가 남았는데 알아들은 메뉴 하나만 통과시킨 경우를 확인했다.
   미확인 표현을 검증 단계까지 전달해 확인하도록 수정했다. 복합 주문 전체를 자동으로 푼 것은 아니다.
