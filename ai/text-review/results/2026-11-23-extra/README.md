# 집 PC 추가 실험과 공백 보정 0.5

기존 집 Docker Qwen3.5 0.8B로 실제 요청했다. 학교 Qwen3.5 9B에는 접근하지 않았다. [팀 공유 PDF](team-share.pdf)는 4쪽이다.

## 기능별 반복 비교

기존 개발 문장 24개(줄임말·메뉴 표기·짧은 문맥 답변 각 8개)를 3회 반복했다. 원문, 용어·표기만 정리, 용어·표기와 문맥 보강의 3조건에 **같은 명시적 문맥**을 제공했다. 문맥 유무가 아니라 문장에 알려진 문맥을 명시하는 효과를 비교한다. 같아진 입력은 같은 문장·회차 안에서 응답을 공유했다. 회차 사이에는 새로 호출했다. 실제 요청은 129회였다.

| 종류 | 원문 | 용어·표기만 | 용어·표기+문맥 |
|---|---:|---:|---:|
| 승인 줄임말 | 3/24 | 12/24 | 12/24 |
| 메뉴 표기 | 12/24 | 12/24 | 12/24 |
| 짧은 문맥 답변 | 0/24 | 0/24 | 6/24 |

모든 숫자는 검수 전 정답 초안의 **응답 전체 조건 일치 관측 수**다. 반복을 독립 표본으로 세지 않는다. 메뉴 표기는 이 표본에서 개선이 없었다. 전체 재점검 조건은 24개 모두 3회 같은 JSON을 반환했지만, 3회 모두 전체 조건이 맞은 것은 10개뿐이었다. 일관된 오답도 있었다. 원문은 69/72, 나머지는 72/72 정상 API·JSON이다. 질문 내용의 실제 적절성은 이 자동 채점에 포함하지 않는다.

## 실제 TTS와 STT 연결

MeloTTS Korean CPU로 기존 개발 문장 8개를 새로 합성했다. 각 PCM16 원음과 -12dB 파일, 총 16개에 실제 SenseVoiceSmall CPU INT8를 실행했다. 파형 크기만 바꾸었고 새 소음은 추가하지 않았다. 두 조건의 STT 출력은 8쌍 모두 같았다. 합성 원문 대비 문자 오류는 조건별 2/67자다. 사람·고령자·실제 소음의 CER로 해석하지 않는다. 동일한 8개 합성을 16번 생성한 것도 아니다.

각 STT 결과를 고정한 뒤 보정 0.4와 0.5에서 실제 Qwen에 각각 30회 요청했다. 이 전후 비교에서도 정답표는 요청에 넣지 않았다. 음성·STT를 새로 실행한 결과로 표시하지 않는다.

## 발견한 문제와 0.5 변경

실제 STT가 `따 뜻한`, `휘 핑`, `빼 고`처럼 단어 내부에 공백을 넣었다. 등록된 온도·옵션·정정 표현 내부의 공백만 붙이는 전처리를 추가했다. 새 문자·수량·온도를 추정하지 않는다. `아 한 잔`을 `아아 한 잔`으로 바꾸지 않는다. 정정 표현을 정리한 뒤 보호 여부를 확인해 임의의 메뉴 오타 확정을 막는다. 원문과 단계별 위치 좌표를 보존한다.

공백은 정리됐지만 두 음량 조건 각각 Qwen 응답 전체 조건 일치는 **1/8 → 1/8**, 올바른 필드 수락은 **0/8 → 0/8**이었다. 개선됐다고 주장하지 않는다. 메뉴 추가 환각, 메뉴 혼동, 의도·질문 상태 모순이 남았고 검증 단계에서 차단·확인으로 처리했다. 차단을 주문 성공으로 세지 않는다.

기존 개발56개의 요청 문장·문맥 보강·판정 플래그는 0.4와 0.5에서 같았다. 과거 STT43개 중 H032 한 개는 `빼 줘` 공백만 달라졌다. 그 한 건을 새로 2회 요청해, 원문 형식 실패와 재점검 경로 보류를 기록했다. 43개 전체를 새로 측정한 것으로 표시하지 않는다.

## 시간과 재현

0.5 재점검 함수에 같은 개발56개를 100회 입력했다. 5,600회 관측 중앙값 0.089ms, p95 0.385ms, 최대 1.089ms다. 별도로 측정한 첫 공백 입력 호출은 8.135ms였다. 모델 요청 시간은 포함하지 않으며 새 음성 표본 수가 아니다. 추가 검사 중 CPU 음성 작업을 병행한 구간이 있어 순수 모델 속도 벤치마크로 쓰지 않는다.

새 합성8개의 MeloTTS 생성 중앙값은 약 3.10초, 공유 초기 로딩은 약 8.83초였다. 집 PC(Ryzen 5 7500F / RAM32GB / RTX4060)의 측정이며 학교·노트북·실제 안내 문장의 체감 지연으로 일반화하지 않는다.

`run_component_check.py --profile home`으로 반복 실험을 재현한다. 학교에서는 `4_학교기능별반복비교.cmd`를 사용할 수 있다. `--validate-only`는 연결 없이 입력만 확인한다. 학교 API 지원과 실제 9B 결과는 미검증이다. 실제 요청·응답·소스 스냅샷·합성 WAV는 개인 전달용 ZIP의 추가_집실험기록에 보관한다.
