# 2026-11-23 집 개발 점검

선정 모델을 바꾼 실험이 아니다. 기존 집 Docker `Qwen/Qwen3.5-0.8B`로 문장 재점검과 검증 경로를 확인했다. **학교 Qwen3.5 9B는 미검증**이다.

측정 장비는 집 PC의 Ryzen 5 7500F / RAM 32GB / RTX 4060 8GB다. SenseVoice는 CPU INT8 4스레드, Qwen은 기존 vLLM GPU bfloat16 구성이다. 장비가 다른 학교 PC·Intel 노트북의 시간으로 일반화하지 않는다.

## 무엇을 확인했나

| 구분 | 자료 | 결과 |
|---|---|---|
| 개발 문장 | 직접 작성한 56개; 엄격한 응답 조건 채점 44개 | 전체 조건 일치 8/44 → 13/44 |
| 핵심 슬롯 | 위 자료 중 단일 메뉴 40개, 메뉴·수량·온도·필수 휘핑 128개 | 83/128 → 93/128; 모두 맞은 문장 14/40 → 21/40 |
| 예전 실제 STT 문장 | 마이크 49요청 → 서로 다른 원문 45개 → 공백·문장부호 묶음 43개; 문장 자체의 정답 초안이 가능한 18개만 채점 | 전체 조건 일치 1/18 → 4/18; 핵심 슬롯 30/54 → 36/54 |
| 실제 연결 | 동봉 합성 WAV 1건을 실제 SenseVoiceSmall → 현행 재점검 → 실제 집 Qwen → 검증으로 실행 | 아이스 아메리카노 1잔 필드 통과. 사람 마이크 성능 표본은 아님 |

API·JSON 정상은 개발 56개 A55/B56, 예전 STT43개 A39/B42다. 실패도 전체 채점 분모에 포함했다. 개발 문장 개선 5개 중 1개는 원문 출력 잘림 해소다. 양쪽 정상 JSON 43개로 제한하면 전체 조건 일치 8 → 12개다.

정답은 사람이 독립 검수하기 전인 **개발 초안**이다. 예전 음성 원본·검수 전사가 없어 CER를 계산하지 않았고, 문맥이 없는 짧은 답변이나 복합 요청을 임의로 정답 처리하지 않았다. 자료별 결과를 합쳐 독립 표본 수나 전체 주문 성공률로 제시하지 않는다.

개발56에서 정답 초안상 완성된 단일 추가 입력은 24개이며, B 경로에서 올바른 필드 수락은 11개였다. 나머지는 통과로 세지 않았다. 모두 차단해서 안전한 것으로 보이는지 확인하기 위해 이 분모도 함께 제시한다.

## 실제로 고친 오류

`아아 하나랑 아봐라 하나 주세요`에서 미확인 메뉴가 남았는데 아메리카노만 수락 가능으로 판정하던 검증기 0.1의 오류를 찾았다. 재점검의 미확인 정보를 검증 단계에서도 확인하고, 알려진 메뉴 뒤에 추가 요청이 이어지면 단일 추가 주문으로 단정하지 않도록 0.2에서 보완했다.

원본 모델 응답을 유지한 **43개 저장 응답의 재검증**에서 B 경로의 잘못된 수락은 1 → 0건, 올바른 필드 수락은 4 → 4건이었다. 새 모델 호출은 0회다. 이것은 발견한 개발 오류의 회귀 점검이며 새 환경의 무오류 증거가 아니다. 복합 주문을 자동으로 해결했다는 뜻도 아니다.

## 시간과 남은 일

개발56 재점검 중앙값 0.083ms, 최대 0.552ms. Qwen 요청 중앙값은 A 2346.131ms / B 2645.243ms다. 캐시·호출 순서·출력 길이 차이가 있어 Qwen 속도 향상을 주장하지 않는다.

실제 합성 WAV 연결에서는 3.057초 음성을 SenseVoice CPU INT8로 인식했다. 로딩 1119.401ms, 인식 55.03ms다. 한 건의 연결 확인이고 사람 음성 평균 성능이 아니다.

학교에서는 같은 조건의 A/B를 **선정한 9B**에 실행하고, 팀원이 정답·질문 의미를 검토해야 한다. 마이크·고령자·소음 환경, 자동 대화 상태와 장바구니의 통합 검증은 별도다.

원본 요청·응답·실험별 소스 스냅샷은 개인 전달용 묶음에 보관한다. Git에는 집계와 직접 만든 문장 비교표만 올린다.
