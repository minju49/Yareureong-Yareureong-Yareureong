# 첫 주문 확인 후 화자 추적 검증

## 같은 분리 트랙에서 선택 규칙 비교

AI Hub의 ‘라벤더’ 녹음을 합성해 첫 발화에서 올바른 화자를 고른 세션을 대상으로 검증했다. 첫 발화와 후속 발화는 서로 다른 원본이다. 별개의 화자로 구성한 설정용 24세션과 검증용 60세션을 사용했다. 후속 발화에서는 양쪽 호출어 위치를 음소거했다. 검증용 각 세션에서 주문자가 말하는 혼합과 주문자 없이 배경 화자 두 명이 말하는 혼합을 각각 시험했다.

| 같은 MossFormer2 출력에서 고른 방식 | 같은 화자 선택 | 다른 화자 또는 모호한 트랙 선택 | 주문자 발화 보류 | 주문자 없는 발화 승인 | 후속 CER |
|---|---:|---:|---:|---:|---:|
| 더 큰 트랙 선택 | 26/60 | 34 | 0 | 60/60 | 72.26% |
| 첫 음성과 가장 비슷한 트랙 선택 | 58/60 | 2 | 0 | 60/60 | 19.64% |
| 유사도 0.40 이상과 두 후보 차이 0.20 초과 확인 | 41/60 | 0 | 19 | 1/60 | 39.28% |

후속 CER은 같은 음성 인식기로 계산했고 보류는 문장 삭제로 집계했다. 점수 차이를 적용한 경로는 승인 오류를 줄이는 대신 주문자가 말한 경우도 19건 보류했다. 키오스크 시연은 이 경로를 사용한다.

### 인식 문장 예시

- 목표 후속 발화 — “내과 진료실에 어떻게 가는지 안내해 줘.”
- 배경 발화 — “심심하니까 내 말동무해 줄래?”
- 혼합 음성 인식 — “내 의심심하니까 내 말동무 해줄래”
- 더 큰 트랙 선택 — “궁심하니까 내 말똥무 해줄래”
- 첫 음성과 비교 후 인식 — “내과 진료실에 어떻게 가는지 안내해줘”

다른 사례에서 목표는 “에어컨 최대 강풍으로 틀어 줘”, 배경은 “지금 손님 내리시니까 뒷자리 차 문 바로 열어 줘”였다. 큰 트랙을 고르면 배경 문장이 나왔고, 유사도 0.34와 0.19로 둘 다 하한에 못 미쳐 주문 경로는 보류했다.

## “주문할게요” 로컬 연동 확인

RTX 5060의 로컬 서버에서 합성 WAV를 HTTP API에 보내 동작을 확인했다.

- 첫 WAV — “주문할게요. 아이스 아메리카노 한 잔 주세요.” → “아이스 아메리카노 한 잔 주세요”. 확인 전에는 후속 요청을 거절했다.
- 동일 합성 화자의 후속 WAV — “따뜻한 걸로 바꿔 주세요.” → “따 뜻한 걸로 바꿔 주세요”.
- 다른 합성 화자의 후속 WAV — “어제 새로 생긴 가게를 구경하고 왔어.” → 화자 불명확으로 보류했다.
- 세션 종료 후 같은 토큰의 후속 요청과 재확인을 거절했다. 기존 OFF 경로에서도 동일한 음성 인식기를 호출했다.

브라우저에서 음성 처리 모드와 호출어 안내를 확인했다. “주문할게요” 실제 마이크, 현장 동시 발화, 메뉴·장바구니 자동 반영은 별도 검증 범위다. 60세션의 성능 수치는 ‘라벤더’ 합성 실험 기준이다.
